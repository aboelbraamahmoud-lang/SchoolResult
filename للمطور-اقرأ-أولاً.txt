مرصد النتائج المدرسية — حزمة المطور 6.9.0

1) نقطة البداية
- التطبيق النهائي: index.html + app.js + style.css + supabase.js.
- مصدر التطوير الحالي داخل source/.
- ليست هذه شجرة React/TypeScript الأصلية؛ source/base/app.js هو bundle أصلي وتطبّق source/build.cjs طبقة patches وخدمات مقروءة من source/src/.
- لا تعدّل app.js النهائي يدويًا؛ عدّل source ثم أعد البناء.

2) البناء والاختبار
من داخل source/:
node --expose-internals build.cjs
node --expose-internals tests/regression.cjs
node --expose-internals tests/cloud.cjs
node --expose-internals tests/structure.cjs
node release.cjs
node tests/release.cjs

3) بنية 6.8 الجديدة
- source/src/catalog.js: اشتقاق/تطبيع grades, classes, subjects, teachers, teacherAssignments؛ مطابقة التكليفات؛ الملف الأكاديمي؛ نموذج لوحة القيادة.
- source/src/master-ui.js: شاشة الهيكل الأكاديمي، خريطة التكليفات، الملف الأكاديمي للطالب، ولوحة القيادة التنفيذية.
- source/src/patches/matching.js: إذا كان ملف النتيجة بلا معلم، المطابقة الإلزامية من subject + className؛ لا guessing عند غياب/تعارض التكليف.
- source/src/patches/domain.js وengine.js: Workspace Schema 7 وترحيل بيانات 6.7.x.
- source/src/imports.js: حفظ الكتالوج بعد دمج المعلمين أو النتائج.
- نموذج-استيراد-نتائج-المدرسة.xlsx: لا يحتاج عمود المعلم؛ يمكن رفع مادة مادة.

4) نموذج البيانات الحالي
- Workspace JSONB ما زال وحدة الحفظ السحابية authoritative لسلامة الترقية وعدم كسر RPC الحالي.
- Schema 7 يضيف catalogs مترابطة: grades/classes/subjects، Teacher ID، وteacherAssignments المرتبطة بمعرفات classId/subjectId/profileId.
- الربط المنطقي المركزي للتكليف واحد؛ الواجهات المختلفة تعدّل السجل نفسه ولا تخزن نسخة منفصلة للعلاقة.
- النتائج تحفظ المعلم التاريخي لكل اختبار بعد حل التكليف وقت الاستيراد، لذلك تغيير التكليف لاحقًا لا يعيد كتابة التاريخ.

5) قاعدة البيانات والأمان
- المشروع: school-results.
- RLS إلزامي، ولا service_role أو secret في الواجهة.
- school_save يستخدم revision + write_id لمنع overwrite ودعم idempotent retry.
- authenticated لديه أقل الصلاحيات اللازمة؛ الكتابات الحساسة تمر عبر RPCs المحمية.
- school_archive_list metadata فقط، school_archive_get يجلب نسخة عند الطلب، school_archive_delete للحذف المحمي.

6) الأرشيف والحفظ
- الحفظ التلقائي مجمّع لتقليل الكتابات.
- لا توجد نتائج authoritative في localStorage/IndexedDB؛ السحابة هي المصدر.
- نقطة الاستعادة تُنشأ قبل تغييرات الهيكل الأكاديمي المهمة.

7) التحديثات
- update.ps1 يتحقق من SHA256 ويرفض downgrade وفق Semantic Version.
- release.cjs يعيد إنشاء update-manifest.json وchecksums.sha256 بعد أي تعديل نهائي.
- source/tests/output مستثنى من checksums لأنه ناتج متغير.

8) تقرير مقارنة المواد
- SR63.gradeSubjectPages: صفحة لكل grade.
- SR63.gradeSubjectMatrix: داخل كل مادة ترتب الشعب رأسيًا، وأمام كل شعبة المعلم والنجاح والتحصيل.
- SRGradeSubjectsReport: العرض والطباعة Landscape.

9) اتجاه 7.0
- إعادة استخراج التطبيق إلى React/TypeScript منظم.
- تطبيع results/audit/imports/catalog إلى جداول PostgreSQL مستقلة عند الحاجة لأحجام أكبر وتعدد مستخدمين متزامن.
- صلاحيات أدوار متعددة وتحديثات موقعة رقميًا وتوافق schema صريح.
