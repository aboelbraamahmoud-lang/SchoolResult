# مرصد النتائج المدرسية — SchoolResult Web

الإصدار الحالي: **6.9.20**

هذه هي حزمة الويب الكاملة الجاهزة لوضعها في جذر مستودع GitHub. ملفات التشغيل (`index.html`, `app.js`, `style.css`, `supabase.js`) موجودة مباشرة في جذر المستودع، بينما السورس والاختبارات وملفات SQL موجودة داخل `source/`.

## التشغيل والنشر

المشروع واجهة ويب ثابتة مرتبطة بـ Supabase. عند النشر يجب أن يكون `index.html` في جذر موقع الاستضافة.

## التطوير

```bash
npm run install:source
npm run verify
```

`npm run verify` يعيد بناء ملفات الواجهة، يشغل اختبارات التقارير والانحدار والسحابة والبنية، ثم يعيد توليد manifest وchecksums ويفحص الإصدار النهائي.

## قواعد مهمة

- لا تضع `service_role` أو أي مفتاح سري داخل الواجهة.
- حافظ على RLS وسياسات الوصول في Supabase.
- لا تحذف `source/` أو الاختبارات أو SQL migrations عند إصدار نسخة جديدة.
- يجب توحيد رقم الإصدار في `package.json` و`version.json` والـruntime قبل النشر.


## Supabase Keep-Alive

الإصدار 6.9.20 يضيف قراءة صحية آمنة مرتين يوميًا لتقليل احتمال توقف مشروع Supabase المجاني بسبب الخمول.
نفّذ مرة واحدة ملف `source/db/6.9.19_keep_alive.sql` في SQL Editor، ثم يمكن تشغيل
`.github/workflows/supabase-keepalive.yml` يدويًا أو تركه يعمل صباحًا ومساءً.
الآلية تستخدم مفتاح النشر العام الموجود أصلًا في التطبيق، ولا تستخدم `service_role`.


## استيراد الهيكل الأكاديمي من ملف واحد

من الإصدار 6.9.20 يمكن رفع `نموذج-قاعدة-بيانات-المعلمين.xlsx` مرة واحدة ليقوم النظام تلقائيًا بإنشاء الصفوف والشعب والمواد والأقسام والمنسقين والمعلمين وخريطة التكليفات. إذا كان عمود «اسم منسق المادة» فارغًا، يعتمد النظام أول معلم ظاهر للمادة منسقًا لها.
