# مرصد النتائج المدرسية — SchoolResult

**الإصدار: 6.10.7 — Official XLSX Range Recovery**  
تاريخ الإصدار: 2026-10-10

إصدار تثبيت شامل بعد مراجعة منطق البيانات والاستيراد والهوية الأكاديمية والتقارير والطباعة وجودة البيانات والأمان وتجربة الاستخدام ونسخة Windows والنشر السحابي.

## جديد 6.10.7 — إصلاح الملف الحقيقي متعدد الشعب

- الاختبار بملف نتائج حقيقي: 10 مواد، 160 طالبًا، 10 مجموعات بينها ESE.
- اكتشاف خانات الطلاب خارج نطاق Excel المعلَن الخاطئ `A1:CV5`؛ لم يعد الاستيراد يتوقف عند أول طالبين.
- الحفاظ على الرقم الأكاديمي في عمود «الرقم» إذا كان طويلًا (ثمانية أرقام فأكثر) مع استمرار اعتبار 1، 2، ... أرقامًا تسلسلية.
- المادة التي لا توجد بها درجات أو حالات مرصودة تُعرَض مع تنبيه وتُستبعد من استيراد الدرجات دون تصفيرها.
- إثبات نجاح المصالحة والاعتماد لعدد 1440 نتيجة في 9 مواد، و160 طالبًا، و10 مجموعات؛ إعادة الرفع دون تكرار.

## سجل الإصدار السابق 6.10.6 — إصلاح عناوين مجموعات الشعب

- اكتشاف عنوان الشعبة الجديدة في أي عمود داخل ورقة Excel، مثل `الشعبة: 7/2` في العمود الأول، وليس فقط في عمود «الشعبة الصفية».
- التعامل مع عنوان الشعبة إذا جاء داخل عمود الاسم أو في صف عنوان مدمج، والانتقال إلى المجموعة الجديدة مع الحفاظ على هوية كل طالب.
- قراءة عناوين الأعمدة المتكررة حتى إذا تغيّر موضعها بين أقسام الملف؛ وتوريث الشعبة للخلايا الفارغة **فقط** من آخر عنوان شعبة مؤكد.
- التعامل مع تنسيقات `07/1` و`7/1` و`07/ESE`، ومنع اعتبار عنوان المجموعة اسمًا لطالب وهمي.
- منع اعتماد **أي** دفعة يكتشف القارئ أخطاء تمنع تحديد شعبة طالب؛ الحماية موجودة في واجهة الاعتماد ودالة `commitImport` أيضًا.
- عرض توزيع النتائج لكل شعبة في المعاينة (مثال: `7/1: 18 | 7/2: 18 | 7/3: 18 | 7/4: 18`) مع عدد أخطاء قراءة الملف وأرقام صفوفها.
- خمسة ملفات XLSX فعلية للاختبار تغطي النصوص والعناوين المتحركة والشعب الأربع وطلاب الدمج؛ إضافة اختبارات تمنع العودة للخلل.
- بدون حذف نتائج قائمة أو تعديل قاعدة Supabase الإنتاجية أو تغيير تصميم التقارير.

**هام:** ملفات XLSX المستخدمة للاختبار ملفات اصطناعية واقعية؛ يجب التحقق من ملف النتيجة الأصلي للمدرسة بعد تثبيت النسخة الجديدة للتأكد من تطابق تنسيقه. إذا سبق اعتماد دفعة خاطئة تُستعاد تلك الدفعة وحدها من نقطة استعادة / سجل الدفعات قبل إعادة الاستيراد؛ لا تُفرغ كل نتائج المدرسة.

## أهم التحسينات

- هوية طالب موحدة تمنع تضخم العدد عند رفع عدة مواد، مع الحفاظ على الطلاب الحقيقيين ذوي الأرقام الأكاديمية المختلفة حتى لو تطابقت الأسماء.
- مصالحة واضحة قبل اعتماد الاستيراد: الطلاب، النتائج، المواد، الشعب، الربط، الجديد، المحدث، المتطابق والتعارضات.
- تفريغ نتائج تقييم واحد فقط مع نقطة استعادة، أو تفريغ جميع التقييمات عند اختيار ذلك صراحةً، دون المساس ببقية النتائج عند التفريغ الجزئي.
- دعم الملف المجمع والملفات المفردة، مع مرادفات محسنة للحوسبة والتربية الفنية وغيرها.
- فحص سلامة الهيكل الأكاديمي والتكليفات والمنسقين وتعارضات الهوية.
- دلالات دقيقة في التقارير متعددة المواد: عدد الطلاب منفصل عن عدد النتائج المرصودة.
- كشف نتيجة طالب رسمي يتضمن الرقم الأكاديمي، المادة، الدرجة الكلية، درجة الطالب، النسبة، التقدير، والتنبيه إلى طريقة احتساب الإجمالي، مع توقيعات النائب الأكاديمي والمدير.
- معاينات مركز التقارير وطباعة نتائج الطلاب أصبحت تُجهّز عند الطلب بدل توليد جميع الصفحات الثقيلة لحظة فتح الشاشة.
- إزالة اسم منسق المادة من ترويسة التقارير والإبقاء عليه في منطقة التوقيعات السفلية.
- اختيار دائم للمواد المحتسبة في ملخصات ورسوم لوحة القيادة؛ استبعاد مادة من الرئيسية لا يحذف بياناتها ولا يغيّر تقاريرها التفصيلية.
- رسوم أوضح للمقارنات ولوحة القيادة مع إظهار النجاح والتحصيل وحجم العينة بصورة مباشرة.
- تقرير تنفيذي من صفحة واحدة، وتحسين مقارنة الاختبارات والعينة المشتركة، وتحويل تقرير الطلاب المستهدفين إلى متابعة قابلة للتنفيذ.
- تقسيم التقارير العريضة إلى صفحات أصغر بدل ضغط الخطوط إلى أحجام غير مقروءة.
- تحسينات تصميمية موحدة للبطاقات، حالات التركيز، لوحات المصالحة والجودة والطباعة الرسمية.
- Security Headers لنشر Vercel، مع بقاء نسخة Desktop معزولة عن Node وتقييد الصلاحيات والروابط الخارجية.
- تقليص patch التقارير الكبير بإزالة شعار الوزارة المضمّن Base64 واستخدام الأصل الرسمي كملف مستقل.

## بنية المستودع

- ملفات الجذر (`index.html`, `app.js`, `style.css`, `supabase.js`) هي نسخة الويب الجاهزة للنشر.
- `source/` هو السورس القابل للصيانة والاختبارات وملفات SQL.
- `desktop/` يحتوي مصدر Electron فقط. مجلد `desktop/web/` مولد تلقائيًا ولا يُحفظ في GitHub.
- `.github/workflows/build-windows-setup.yml` يبني Windows Setup ويختبر أن التطبيق لا يغلق فور التشغيل.
- `.github/workflows/verify.yml` يشغل اختبارات المشروع قبل اعتماد التغييرات.
- `.github/workflows/supabase-keepalive.yml` ينفذ قراءة صحية دورية آمنة باستخدام المفتاح العام فقط.

## دورة التطوير المعتمدة

1. التعديل داخل `source/`.
2. تثبيت اعتماديات السورس: `npm --prefix source ci`.
3. تشغيل `npm run verify`.
4. رفع الملفات الناتجة والسورس إلى GitHub.
5. لنسخة Windows: **Actions → Build Windows Setup → Run workflow**.

## قاعدة البيانات

ملفات Supabase وRLS وSQL migrations موجودة تحت `source/db/`. لا تستخدم الواجهة الأمامية `service_role`. لم يتضمن هذا الإصدار هجرة مدمرة لقاعدة الإنتاج؛ الانتقال المستقبلي من Workspace JSONB إلى جداول علائقية مستقلة يجب أن يتم في Migration منفصل بعد اختبار تطابق كامل وربط مشروع Supabase الصحيح للفحص الحي.
